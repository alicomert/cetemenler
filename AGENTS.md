# AGENTS.md

## What this repo is

Static, build-less multi-page website template ("Printop" by wowtheme7): 19 flat `.html` files at
the repo root plus one `assets/` tree. No `package.json`, no bundler, no framework, no tests, no
lint, no CI, not a git repo.

There is intentionally no build step — **keep it plain HTML**. Do not introduce `package.json`,
npm scripts, a bundler, or a framework.

Serve over HTTP before verifying (`npx serve` or `python -m http.server`). Opening via `file://`
breaks GSAP ScrollSmoother / AOS because they measure real layout.

## SCSS is the source, `main.css` is generated

- Edit `assets/sass/**/*.scss`. `assets/css/main.css` (+ `.map`) is compiled output and is
  committed; HTML links `main.css` only. Editing `main.css` by hand gets overwritten.
- Compile with: `npx sass assets/sass/main.scss assets/css/main.css`
- `main.css` and `main.css.map` are currently **Dart Sass** output (rebuilt after the GSAP/AOS
  removal). The original template shipped LibSass output, which kept hex colors as hex; Dart Sass
  emits `rgba(...)` instead. Any comparison against the pristine template will show a large but
  purely cosmetic diff.
- SCSS uses legacy `@import`, so Dart Sass prints ~87 deprecation warnings. Harmless; pin
  `sass@1.x` if the noise is annoying.
- Import order in `main.scss` (`abstracts` → `components` → `utilities` → `layout` → `partials`)
  matters — `abstracts/_functions.scss` provides `rem()`. Don't reorder.
- `assets/sass/layout/_slick.scss` is **not** imported by `layout/_index.scss`, and no Slick
  library is loaded anywhere. Dead file. Carousels are Swiper
  (`components/_slider.scss` + `swiper-bundle.min.js`).
- The `layout/_preloader.scss` and `layout/_custom-cursor.scss` partials were deleted along with
  their features. Don't re-add them.
- Animation hook classes such as `.custom-fade-animation`, `.text-reveal`, `.animated-title`,
  `.splitTextStyleOne`, `.card-animation` and `.move-on-cursor-hover` are **left in the markup but
  have no CSS and no JS**. They are inert, and `move-on-cursor-hover` elements now sit still
  instead of following the mouse. Nothing currently drives them.

## Which page uses which styles

Style partials do not map 1:1 to HTML files; two design generations coexist.

| Pages | Partials |
|---|---|
| `index.html`, `shop-new.html`, `shop-details-new.html` | `partials/home-new/*` — new design |
| `index-2.html` | `partials/home-one/*` — old design |
| `index-3.html`, `index-4.html` | `home-one`-derived, reuse a few of its sections |
| everything else | shared `layout/`, `components/`, `utilities/`, `partials/inner-pages/` |

The new-design pages are the only ones with `<html class="home-style-gradient font-size-style-new">`.
Those two classes switch the type scale and gradient background
(`partials/home-new/_home-style-gradient.scss`) — dropping them silently changes the whole page.
All other pages have `<html class="">`.

## Utility classes are generated, not Tailwind

- `tw-*` classes (`tw-px-6`, `tw-gap-4`, `tw-h-320-px`, `tw--me-16-px`) are emitted by
  `assets/sass/utilities/*` from the `$spaces` / `$font-sizes` / `$colors` maps in
  `abstracts/_variable.scss`. If a spacing/color class doesn't exist, add it to the map or the
  `@each` loop — never hand-write page CSS for it.
- Unprefixed `bg-main-600`, `text-white`, `hover-text-heading`, `line-clamp-1`, `rounded-lg`
  are generated by the same loops. Bootstrap 5 grid/utilities (`d-flex`, `py-80`, `col-lg-8`)
  are used alongside.
- Theme color lives as three CSS vars: `--main-h/-s/-l` (and `--main-two-*`) in `:root`. Change
  those to re-tint the whole site; don't hardcode hex in pages.
- RTL overrides live in `partials/_rtl.scss` under `[dir="rtl"]` (the settings panel toggles
  `dir` at runtime). Broken-in-RTL fixes go there.

## JS: what actually loads

All 19 pages load the **same 10 scripts in the same order** (verified identical).

- **GSAP and AOS have been removed from this project.** `custom-gsap.js`, `gsap-plugin.js`,
  `aos.js`, `aos.css` and the leftover `gsap.min.js` / `ScrollTrigger.min.js` /
  `SplitText.min.js` were deleted along with all their markup hooks
  (`.preloader`, `.cursor`, `.dot`, `#magic-cursor`, `#ball`, `data-aos-*`,
  `data-animate`, `clip-animation`, `clip-animation-img`). Do not reintroduce them.
- The site is now free of scroll-driven animation: no ScrollSmoother smooth scroll, no
  ScrollTrigger pins, no SplitText. `#smooth-wrapper` / `#smooth-content` divs remain as plain
  containers — they are no longer wired to anything.
- `assets/js/boostrap.bundle.min.js` is misspelled (missing `t`) and every page links that exact
  path. Don't "correct" it without renaming the file in all 19 pages.
- `main.js` = all jQuery behavior (mobile menu, sliders, accordions, forms, toasts, quantity stepper,
  color picker, marquee, counters).
- `main.js` runs `document.querySelector(".progress-wrap path").getTotalLength()` **unguarded** at
  ready time. A new page missing `<div class="progress-wrap"><svg><path>` will silently kill every
  handler after it. Same class of dependency: `#toast-container` (toasts), `.mobile-menu` +
  `.toggle-mobileMenu` + `.close-button` (drawer), and `.side-overlay` (shared by the drawer and the
  shop category sidebar). Copy the boilerplate from an existing page.
- The mobile sidebar drawer is **CSS-class driven**, not tweened: `openMobileMenu()` /
  `closeMobileMenu()` in `main.js` toggle `.active` on `.mobile-menu` and `.show` on
  `.side-overlay`. Animation comes from `.mobile-menu.active { transform: translateX(0) }` and
  `.side-overlay.show`. Touch either side and you must update both.
- All 19 `<title>` tags are identical (`Printop - Modern Printing & Print Shop HTML Template`).
- Header, footer, settings panel, scroll-to-top and toast container markup is
  **inlined and duplicated in every HTML file** — there is no templating. Changing nav or footer
  means editing 19 files; use a multi-file replace and verify the count.

## External / CDN dependencies

- `assets/js/phosphor-icon.js` injects Phosphor Icons CSS from
  `https://unpkg.com/@phosphor-icons/web@2.1.1/...` at runtime. Icons are **not vendored** —
  offline preview shows no icons anywhere.
- Google Fonts are pulled by an `@import url(...)` at the top of `abstracts/_variable.scss`,
  which gets compiled into `main.css`.
- 15 occurrences of `class="las la-home"` (LineIcons) exist in markup, but LineIcons CSS is not
  loaded anywhere — those glyphs render blank. Known gap; leave it unless asked.

## Forms and nav state

- Every `<form>` is `action="#"`; there is no backend. `main.js` intercepts `.form-submit`,
  clears all `input`/`textarea` and shows a success toast. Wiring a real endpoint is manual.
- Nav highlighting uses `dynamicActiveMenuClass` in `main.js`: it matches the last segment of
  `window.location.pathname` against each `li a[href]`. `index.html` / root pins the Home item.
  A new page only highlights if its `<a href="newpage.html">` exists in the header.
- The mega menu links `index-2/3/4` plus 8 `coming-soon-img.png` placeholders (Home 5 / Home 6).
  Those are intentional demo placeholders, not missing assets.

## Verification

No automated checks exist and none should be added. Verify by loading the affected page over HTTP
and inspecting in the browser. After any SCSS edit, recompile `main.css` before testing — the
pages will not reflect the change otherwise.
